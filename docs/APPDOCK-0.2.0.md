# AppDock 0.2.0

Дата: 29 октября 2026 года. Исходный аудит: `artifacts/APPDOCK-AUDIT-2026-10-29.md`.

## Просмотр

Готовые файлы доступны в [GitHub Releases](https://github.com/Farbras/appdock/releases/tag/v0.2.0): установщик `AppDock_0.2.0_x64-setup.exe`, отдельный `AppDock.exe` и архив `AppDock-0.2.0-windows-x64.zip`. После локальной сборки эти файлы находятся в `releases/AppDock-0.2.0/`. Приложению нужен WebView2; установщик может скачать его штатным способом. Сертификат подписи выпуска не настроен.

Нативное приложение начинает с чтения состояния компьютера и не запускает очередь самостоятельно. Для безопасной проверки сценариев включите «Настройки → Демонстрационный режим». Браузерный просмотр всегда демонстрационный: `./scripts/npm.ps1 run dev`, затем http://127.0.0.1:1420/.

## Изменения поведения

- Схема очереди 2 хранит текущий `runId` и отдельные записи запусков: дата, режим, исходные параметры выполнения, выбранные версии, задачи и итог. Прогресс относится только к текущему запуску. Старые снимки мигрируют; прерванные задачи восстанавливаются приостановленными.
- «Повторить ошибки» отбирает только `error` выбранного запуска. Отмены, инструкции и блокировки имеют собственные команды. Любой повтор проходит новый план. Можно исправить параметры одной задачи; повторная проверка сохраняет исправления и исходную политику запуска.
- Rust создаёт развёрнутые задачи при подготовке плана и сохраняет их под одноразовым токеном. Исполнитель получает эти же задачи. Состав включает версии, редакции, область, опции, расширения, компоненты Visual Studio, ожидаемые пропуски и ручные шаги. Есть изменение параметров, удаление позиции и новая проверка.
- Зависимости расширений представлены графом задач и упорядочены топологически. Сбой зависимости блокирует зависимые задачи с причиной; независимые продолжаются. Для зависимостей из предыдущего запуска Rust заново проверяет обнаружение или CLI VS Code.
- Смешанная загрузка показывает недоступные позиции в плане. После старта из выбора удаляются только принятые к выполнению продукты; параметры остальных сохраняются.
- Единое сопоставление продуктов учитывает основные и резервные ID, `appdock:<id>` и редакции. Экземпляры Visual Studio считываются через vswhere отдельно, без приписывания Professional/Enterprise к Community. Обнаружение обновляется один раз после завершения запуска; показана дата проверки.
- Ctrl+K закрывает диалог, открывает каталог и переносит фокус после отрисовки. Версия интерфейса берётся из package.json; `version:sync` синхронизирует метаданные Rust/Tauri перед сборкой.
- Импорт достраивает известные зависимости расширений и сообщает об этом. Устаревшее закрепление остаётся видимым до явного выбора последней версии. Порты и другие значения проверяются перед сохранением, Rust повторяет окончательную проверку.

## Новые рабочие разделы

**Готовность компьютера.** WinGet, свободное место, дата обнаружения, число доступных обновлений и незавершённых задач. Неизвестные значения не заменяются вымышленными. Есть подготовка компьютера и повторная проверка обновлений.

**Обновления.** Текущая и доступная версии поступают из реального обнаружения WinGet. Есть множественный выбор, сохраняемые исключения из массового обновления, закрепления профиля, выбор обнаруженной редакции Visual Studio, новый план и официальный ручной маршрут.

**Профиль ПК.** Сохранение выбора или обнаруженного состава, редактирование параметров и политики версии, сравнение с компьютером, JSON-экспорт и импорт с проверкой совместимости. Неподдерживаемые продукты импорта перечисляются явно. Профиль переносит только состав программ и параметры AppDock.

**Наборы.** Создание, название, описание, редактор состава и параметров каждого продукта, дублирование, экспорт/импорт с предварительной проверкой, добавление к выбору, замена и отмена последней замены. Под названием набора показаны мини-иконки его приложений с названиями при наведении; состав обновляется после редактирования, длинный ряд переносится. Политика «последняя» не превращается в закрепление при экспорте.

**Ручные действия.** Инструкция, параметры-памятка, копирование, официальный источник, повторное обнаружение и отдельная отметка пользователя. `user-completed` отличается от подтверждённого обнаружения; результат остаётся в истории запуска.

**История и диагностика.** Группы запусков и продуктов, поиск, фильтры, времена, длительность, последние сообщения, версии, результаты и журналы. Читаемый отчёт и JSON доступны в редактируемом предварительном просмотре. Автоматическое скрытие известных личных путей и ключей дополняется ручным редактированием перед локальным сохранением. Отчёты не отправляются внешним получателям.

**Полученные файлы.** Выбор папки, открытие папки, список файлов с размером, версией при наличии подтверждения, происхождением и описанием проверки. Загрузки разнесены по продуктам и ID задач; доступны удаление отдельных файлов кэша и сведения об ограничениях пакетов. Успех загрузки WinGet не выдаётся за проверку всех вспомогательных файлов или повторную проверку текущего хеша.

## Интерфейс и архитектура

Сохранены русский язык, темы и общий стиль. При узком окне панель выбора раскрывается доступной кнопкой; важные подписи не уменьшаются до 7–10 px. Увеличены области нажатия, сохранён заметный фокус. Каталог по умолчанию показывает Windows, имеет сортировку и видимые снимаемые фильтры, различает способы выполнения и версии. Профили VS Code: базовый, Python, веб, без расширений; состав каждого можно изменить и сохранить.

App.tsx теперь координирует данные и маршруты. Каталог, настройки, история, дополнительные рабочие экраны, панель выбора, параметры, план и общие элементы вынесены в отдельные файлы. Планирование демо и правила состояния расположены в `queue.ts`, хранение и проверка импорта — в `storage.ts`, отчёты — в `diagnostics.ts`, адаптер — в `api.ts`. Граница отдельного экрана показывает возможность повторного открытия при ошибке рендера.

Нативные события `queue-changed` и подписки демо заменили опрос каждые 700 мс. Сверка снимка выполняется раз в 15 секунд. Вывод процессов сохраняется и передаётся не чаще раза в секунду; смены статусов сохраняются сразу. Журналы ограничены по числу строк. Ошибки записи приостанавливают последующие операции и видны пользователю; повреждённые данные по возможности сохраняются в резервной копии. Каталог остаётся доверенным, произвольные команды импорта не поддерживаются.

Диагностические процессы имеют предел 45 с, загрузки — 10 минут. После 20 минут ожидания установщика задача получает «Требуется внимание», наблюдение продолжается. Пауза и отмена ожидающих задач не означают убийство установщика. Закрытие с работающим установщиком откладывается; закрытие при остановленной очереди допускается.

## Проверки

Результаты финального прогона и пути файлов: `artifacts/APPDOCK-RESULT-2026-10-29.md`.

- `npm run check`: каталог, фронтенд-тесты, TypeScript и production-сборка.
- `npm run format:check`, `cargo fmt --check`, `cargo test --locked`.
- Отдельный `live_readonly_windows_discovery`: WinGet, диск и обнаружение без установок.
- `npm run test:ui`: семь требуемых сценариев, смешанная загрузка, Ctrl+K, минимальное окно и масштаб 125%; подставное обнаружение для центра обновлений.
- `npm run sources:check`: отдельная проверка доступности пакетов и Marketplace. Она создаёт датированные MD/JSON-отчёты и не изменяет доверенный каталог. В GitHub Actions добавлены UI-проверки и отдельный ручной workflow проверки источников.

## Конкретные ограничения

1. Реальные установки, обновления и скачивания пакетов этой итерацией не испытывались. Отказ UAC, перезагрузка, потеря сети и зависшие установщики требуют испытаний в отдельной Windows VM. Демо не подтверждает реальную установку.
2. Статус проверки каталога означает доступность ID в источнике, а не испытанную установку. Сохранённые исторические даты реальных проверок остаются датами этих проверок; новые скрипты используют фактическое время.
3. WinGet не всегда сообщает точную версию или процент загрузки; отсутствие подтверждения явно показано. После загрузки WinGet проверяет хеш установщика по своему манифесту. Повторная криптографическая проверка всего кэша и полная офлайн-установка каталога не реализованы.
4. Несколько экземпляров одной редакции Visual Studio требуют выбора и обслуживания через официальный Installer. AppDock показывает экземпляры, но не выбирает один из них для неоднозначной автоматической операции.
5. Серверные параметры являются памяткой: пароли, перенос данных, секретов и пользовательских файлов, создание облачных ресурсов, автоматическое включение WSL/Hyper-V не входят в функцию.
6. У старой схемы очереди не было политики выполнения и границ запусков. Эти записи объединяются в явно мигрированный запуск с прежними значениями по умолчанию. Для новых запусков исходная политика сохраняется точно.
7. Раздел установленного охватывает продукты каталога. Разбор текстового ответа WinGet не угадывает усечённые ID; такие обновления могут потребовать проверки через WinGet или официальный источник.
8. Автоматическое скрытие диагностики основано на известных шаблонах. Перед передачей нужно просмотреть и при необходимости отредактировать содержимое. Файлы отчётов и происхождения не подписываются; сборка приложения также без сертификата.
9. Одна очередь выполняется за раз. Зависимые заблокированные задачи повторяются отдельной командой после исправления зависимости и нового просмотра плана. Файлы истории и рабочего состояния пока находятся в одном ограниченном снимке; отдельное хранилище журналов потребуется при существенно большем объёме истории.
