# Доработки AppDock 0.2.3

Эти изменения включены в выпуск [AppDock 0.2.3](https://github.com/Farbras/appdock/releases/tag/v0.2.3). Ссылки на готовую версию и краткое описание находятся в [README](../README.md) и [описании выпуска](APPDOCK-0.2.3.md).

## Как пользоваться

- **Очередь / история:** раскройте задачу. Результат установщика отделён от готовности; «Проверить готовность» повторяет только проверку. При подтверждённой готовности и известном запуске появляется «Открыть программу». Кнопки краткого итога фильтруют соответствующие задачи. Технический журнал находится в отдельном раскрываемом блоке.
- **Офлайн-набор:** откройте раздел и отметьте пакеты прямо в нём; предварительный выбор в каталоге не требуется. Доступны поиск, выбор всех поддерживаемых пакетов и список недоступных программ с причинами. Подтверждены автономные снимки Python 3.12.10, Git 2.49.0 и VS Code 1.99.3 для Windows x64 со стандартными параметрами установки. Выберите папку: создаётся отдельная подпапка с полными EXE, `manifest.json`, `SHA256SUMS.txt` и `README.txt`. На другом компьютере выберите именно эту подпапку, нажмите «Открыть и проверить набор», затем просмотрите и подтвердите план. Установка проходит через ту же последовательную очередь, используя локальные копии.

Путь к готовому набору можно также вставить вручную. Подготовку можно отменить; закрытие приложения прерывает её безопасно. Изменение параметров и повтор проверки офлайн-плана сохраняют локальный источник.
- **Профиль ПК → перенос настроек:** выберите компоненты для экспорта. Импорт JSON сначала показывает безопасные поля, исключения, наличие приложений и конфликты. Конфликтующие компоненты по умолчанию пропускаются. Отметьте нужное и примените. Резервные копии доступны в том же разделе. Расширения после переноса предлагаются отдельным обычным планом установки.
- **Настройки → фоновая работа:** выберите интервал проверки, уведомления, поведение крестика, предотвращение сна и лимит прямых загрузок. Нажмите сохранение. Автозапуск меняет запись `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\AppDock` текущего пользователя. Он выключен по умолчанию.
- **Трей:** открытие приложения, проверка обновлений, переход в очередь и выход. Расписание работает при запущенном AppDock, включая скрытое окно. Пропущенные интервалы не превращаются в серию проверок; после запуска выполняется одна просроченная проверка. Установки по расписанию не запускаются. Нажатие уведомления об обновлениях открывает центр с выбором, отфильтрованным по закреплениям и исключениям.
- **После перезапуска:** сохранённая очередь предлагает явное продолжение. Для прямых загрузок используются `.part` и `resume.json`; при несовместимом ответе сервера выберите «Скачать заново», прочитайте объяснение удаления частей и проверьте повторный план.
- **Настройки → каталог:** показывает встроенную или подписанную ревизию, дату проверки и доступность источника. После настройки публикации доступны проверка и атомарное применение с перезагрузкой интерфейса. Незавершённые задачи блокируют смену каталога.

## Готовность и ошибки

В задаче сохраняются независимые `installationOutcome` и `readiness`. Отсутствие записи в реестре или сбой последующего обнаружения не превращают успешный код установщика в ошибку установки. CLI-проверка может отдельно сообщить «Не удалось проверить» или «Установлено, требуется действие». Это не подтверждение функциональности всех возможностей приложения.

Скомпилированные адаптеры проверяют Python (версия, `-m pip --version`, актуальный PATH), Git (версия и актуальный PATH), VS Code (версия CLI и наличие выбранных расширений), Node.js и версии файлов Chrome / Firefox в известных папках. Для остальных продуктов возвращается честное ограничение адаптера. После задач расширений перепроверяется родительский VS Code. Изменения PATH читаются из окружения Machine/User в Windows, а не только из старого окружения AppDock. Отдельные CLI имеют тайм-аут 20 секунд; вызовы существующей диагностики Windows ограничены её тайм-аутами.

Python / Node открываются в отдельной консоли, Git — через найденный Git Bash, графические программы — по найденному исполняемому файлу. При отсутствии надёжного запуска кнопка не появляется. Запуск перед нажатием повторно проверяется.

`task-results.ts` переводит известные коды места, UAC/отмены, сети, источников, хеша, занятости установщика и зависимостей. Неоднозначная отмена не выдаётся за доказанный отказ UAC; неизвестная причина явно остаётся неизвестной. Исправление и повтор используют существующие план, параметры, официальные источники и диагностику. Хеши не отключаются; старое ограничение автоматического восстановления WinGet в один повтор сохранено.

## Автономная установка: реальная область поддержки

Поддерживаются **полные EXE x64 фиксированного снимка**: Python 3.12.10, Git 2.49.0, VS Code User 1.99.3. Они могут быть старше онлайн-каталога; фактическая версия показана и в наборе, и в плане. Закрепление другой версии отклоняется. Перед установкой существующая версия сравнивается со снимком; понижение и неопределимое сравнение блокируются.

Источники доверенных SHA-256:

- [Python 3.12.10, манифест Microsoft WinGet](https://github.com/microsoft/winget-pkgs/blob/master/manifests/p/Python/Python/3/12/3.12.10/Python.Python.3.12.installer.yaml).
- [Git 2.49.0, манифест Microsoft WinGet](https://github.com/microsoft/winget-pkgs/blob/master/manifests/g/Git/Git/2.49.0/Git.Git.installer.yaml).
- [VS Code 1.99.3, манифест Microsoft WinGet](https://github.com/microsoft/winget-pkgs/blob/master/manifests/m/Microsoft/VisualStudioCode/1.99.3/Microsoft.VisualStudioCode.installer.yaml).

Внешние зависимости для базового состава этих рецептов не требуются; Python устанавливается без дополнительного launcher. Для продуктов с неподтверждёнными зависимостями автономная поддержка выключена. Расширения Marketplace, Office, веб-установщики, SDK, сетевые компоненты и онлайн-функции не входят. Обычное разрешение WinGet «скачать» не используется как доказательство автономности.

Импорт проверяет схему, известный продукт, точную версию, архитектуру, имя файла, разрешённые опции и **встроенный** SHA-256 рецепта. Сумма из импортированного файла сама по себе ничего не разрешает. Команды и параметры установки создаёт Rust; импорт не содержит исполняемых команд. Пути внутри набора не могут выходить за его канонический корень, в том числе через ссылку / junction. Перед запуском файл копируется в управляемую локальную папку `offline-stage/<uuid>` и снова хешируется. Эти копии сохраняются для диагностики; их можно удалить при закрытом AppDock. Незавершённая подготовка оставляет папку без опубликованного `manifest.json`; такой набор не принимается и может быть удалён вручную.

Для добавления новых автономных версий пока требуется обновить доверенные рецепты в ядре. Полный прогон установщиков Git, VS Code и Python на отдельном чистом компьютере без сети в этой работе не выполнялся. Код локального запуска реализован, но успешность этих установщиков / UAC на всех конфигурациях не заявляется.

## Перенос настроек: безопасность и конфликты

Формат переноса версии 1 содержит только компоненты и значения, без целевых путей или команд. JSONC VS Code / Terminal читается с комментариями; после изменения сохраняется обычный JSON. Исходные байты, включая комментарии, находятся в локальной резервной копии.

- VS Code: разрешённые параметры редактора, сохранения и внешнего вида с проверкой типов; сочетания с ограниченным списком команд и контекстов, без `args`; расширения только из доверенного каталога. Все остальные параметры и сторонние настройки расширений исключаются.
- Git: `core.autocrlf`, `core.safecrlf`, `init.defaultBranch`, `pull.rebase`, `fetch.prune`, `color.ui`, `merge.ff` с ограниченными значениями. Не копируются user/email, aliases, hooks, include, URL, credentials, helpers, SSH и произвольные конфиги. Целевой файл меняется через `git config --file`, сохраняя остальные локальные настройки.
- Terminal: внешний вид и безопасные поля профилей по GUID. `commandline`, `startingDirectory`, `source`, `actions`, `env`, пути и импорт схем цветов исключаются. Существующие команды целевых профилей остаются локальными.

Рассчитаны стандартные профили VS Code Stable, Git текущего пользователя и Windows Terminal Stable / unpackaged. Portable, Insiders, переназначенные HOME/профили и настройки организаций могут потребовать ручного переноса. Отсутствующее приложение / профиль показывается и пропускается. Это перенос настроек, а не установка отсутствующей программы.

Предпросмотр имеет одноразовый токен на 10 минут и отпечатки целевых файлов. Изменение файла после предпросмотра останавливает запись. Перед перезаписью всех выбранных файлов создаётся локальная копия; при ошибке записи выполняется откат. Восстановление также проверяет, что целевой файл не изменился после импорта. Если изменился — автоматическая перезапись останавливается; исходная копия остаётся для ручного сравнения. Локальные резервные копии могут содержать прежние личные значения целевого компьютера; они **не экспортируются**.

## Загрузки, очередь и фон

Прямой HTTP-поток обрабатывается Rust / reqwest. Перед дописыванием проверяются 206, точный `Content-Range`, размер и strong ETag либо Last-Modified, переданный через If-Range. Ответ 200 вместо диапазона, другой валидатор, неправильный диапазон и несовместимый размер не дописываются. Дочитанный до конца файл после прерывания может быть подтверждён ответом 416 только при совпадении общего размера и валидатора. Для неизвестной идентичности предлагается начать заново.

На паузе байты не записываются и скорость обнуляется. Сетевой сбой / штатное закрытие сохраняют часть; явная отмена и «Скачать заново» удаляют её. Части хранятся до решения пользователя, без автоматического срока удаления. Очистка завершённой истории удаляет неиспользуемые части удаляемых задач и сохраняет части, нужные восстановленным задачам. Готовые файлы остаются. Смена папки загрузок блокируется до завершения / отмены незавершённой очереди. Повтор прямой загрузки наследует идентификатор сохранённой части, но новый ID задачи остаётся отдельным.

Новый клиент начинает измерение скорости с нуля и сохранённого количества байтов; время паузы исключается. Сетевые ожидания имеют предел 30 секунд активного ожидания; закрытие / отмена проверяются каждые 100 мс даже во время ожидания сети. Общий предел прямой передачи — 24 часа активного времени. Для исходных Office IMG в каталоге нет опубликованного контрольного хеша: HTTPS / совпадение размера не выдаются за проверку подписи издателя.

Лимит сохраняется в `background.json` и применяется к каждой прямой загрузке, включая подготовку офлайн-набора. Он не управляет WinGet, Marketplace и сторонними мастерами. Для WinGet сохранилась прежняя пауза активного процесса; продолжение скачивания после выхода / перезагрузки не обещается.

Проверки, перенос и смена каталога сериализуются с подготовкой / запуском очереди. Изменение режима не разрешается во время системной операции. Одновременные фоновые проверки не запускаются; ручные повторные запросы в течение 15 секунд используют только что полученный результат. Single-instance plugin защищает процесс, включая запуск при входе. Запрос выхода при установщике / WinGet отклоняется с объяснением: после завершения текущего установщика нажмите выход снова. Прямые загрузки сохраняются; подготовка офлайн-набора прерывается без публикации неполного манифеста. Крестик с настройкой трея скрывает окно.

Блокировка сна выполняется отдельным потоком через `SetThreadExecutionState`, снимается при общей паузе, отсутствии активных задач, завершении и выходе. Отказ Windows сообщается в интерфейс. Уведомления об ошибках / участии и итогах используют один механизм Windows с сохранённым подавлением повторов на сутки. Нажатие toast в Windows обрабатывается пока он виден; активация из Центра уведомлений ограничена используемым [плагином Tauri](https://v2.tauri.app/plugin/notification/). В dev/portable-окружении имя и доставка уведомлений могут отличаться; для окончательной проверки нужен установленный выпуск.

## Публикация обновляемого каталога

Встроенный каталог всегда доступен без сети. Обновление содержит base64 payload и Ed25519-подпись **точных байтов** payload. Payload: `schemaVersion: 1`, возрастающий `revision`, `minAppVersion` и полный массив `apps`.

Разрешено менять только `version`, `description`, `notes`, `checkedAt`, `downloadMb`, `diskMb` существующих продуктов. Список ID, типы, источники, команды, операции, опции, зависимости и адаптеры должны совпадать со встроенным каталогом. Расширения и наборы пока остаются встроенными. До показа React получает именно активный проверенный каталог ядра; при сбое согласования запуск интерфейса останавливается с возможностью повторить.

Для production нужны:

1. Сгенерировать пару Ed25519. **Приватный PEM хранить вне репозитория и приложения**, например в секретах CI. Тесты генерируют собственные временные ключи, которые production не принимает.
2. Подготовить `payload.json`, например на основе `catalog/apps.json` с нужной ревизией и минимальной версией.
3. Передать путь PEM переменной `APPDOCK_CATALOG_SIGNING_KEY` и выполнить `node scripts/sign-catalog.mjs payload.json catalog.signed.json`. Инструмент выводит только публичный ключ base64, подходящий для сборки.
4. Разместить `catalog.signed.json` по постоянному HTTPS-адресу. При сборке задать **публичные** `APPDOCK_CATALOG_URL` и `APPDOCK_CATALOG_PUBLIC_KEY` (32 байта Ed25519 в base64). Пересобрать приложение с этими значениями.
5. Проверить реальный staging-источник и установленный выпуск, затем публиковать production. Подпись самого EXE / NSIS — отдельная настройка сертификата выпуска.

Адрес и ключ production сейчас **не заданы**. Приложение не обращается к тестовому источнику. Механизм проверен отдельными тестами: подпись из Node-инструмента принимается Rust, повреждение и неизвестные команды отвергаются, повреждённый текущий каталог восстанавливается из проверенной предыдущей копии либо встроенного каталога. Применение использует временный файл, `sync_all` и замену; предыдущий проверенный envelope хранится отдельно.

## Совместимость и проверка

Схема очереди остаётся 2. Новые поля необязательны и имеют serde defaults; прежние снимки, профили и localStorage сохраняются. Старые задачи показывают отсутствие результата готовности, пока пользователь не выполнит проверку. Новые отдельные форматы имеют собственную версию 1. Минимальный Rust в Cargo обновлён до 1.90 по MSRV выбранных Tauri-зависимостей; локальная проверка выполнена Rust 1.99.1.

Команды: `npm run check`, `npm run format:check`, `cargo test --manifest-path src-tauri/Cargo.toml`, `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`, `npm run test:ui`, `npm run test:ui:audit`, `npm run test:ui:features`, `npm run bundle`. Для среды этого репозитория предварительно выполните `. .\scripts\build-env.ps1`.

`scripts/native-features-smoke.mjs` работает с уже запущенным **debug EXE в изолированной папке данных и профиле WebView2**, CDP 9226, сессией `artifacts/native-features-session.json`. Он скачивает Python, проверяет / повреждает / восстанавливает только тестовую копию, готовит план и проверяет второй экземпляр. Установщики не запускаются. `APPDOCK_TEST_DATA_DIR` учитывается только debug-сборкой; release не имеет этого переключателя.

Успех браузерного демо не считается доказательством системной интеграции. На этом компьютере read-only адаптеры честно вернули «исполняемый файл не найден» для Python, Git и VS Code; их успешный запуск после установки здесь не проверялся. Автозапуск, удержание сна, полный цикл уведомления с нажатием и установка на чистой машине требуют отдельного нативного приёмочного прогона. Это реализованные интеграции с указанными границами проверки, а не подтверждённые этим окружением сценарии установки.
