## Исправления

- Для Chrome выбран стабильный пакет `Google.Chrome.EXE` с версионной ссылкой Google вместо MSI, у которого воспроизведено несовпадение хеша.
- Если WinGet не находит установленный пакет через `upgrade`, AppDock обновляет источник и повторяет запрос через `install` с тем же ID, версией и областью установки. Это устраняет ошибку сопоставления с записью в реестре, в том числе для VS Code.
- При несовпадении хеша или отсутствии пакета, манифеста либо данных источника добавлен один повтор после обновления источника `winget`. Проверка SHA-256 остаётся включённой.
- Ошибки WinGet получили конкретные пояснения; команды и коды завершения доступны в журнале задачи.
- Сохранено обнаружение Chrome, ранее установленного через MSI.

## Проверено

18 модульных тестов Rust, 13 тестов фронтенда, проверка форматирования, реальное обнаружение программ в Windows и production-сборка. Chrome EXE и VS Code скачаны через WinGet с успешной проверкой SHA-256; их установщики при проверке не запускались.

Для интерфейса нужен Microsoft Edge WebView2 Runtime; установщик AppDock скачает его при отсутствии. Для установки программ из каталога нужны WinGet / App Installer и интернет. Node.js и Rust для запуска готовой версии не требуются.

`SHA256SUMS.txt` содержит контрольные суммы готовых файлов. Архив `AppDock-0.1.1-source.zip` содержит исходный код.
