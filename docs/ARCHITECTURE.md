# AppDock

Изменения после аудита 2 ноября: [отчёт о выполнении](AUDIT-FIXES-2026-11-02.md).

Общие правила действий находятся в `catalog.ts`, сравнения профиля и обновлений — в `domain.ts`, отображения — в `display.ts`. Rust повторно проверяет доверенный каталог. Файловый API требует явный режим; нативные команды отклоняют деморежим, удаление требует подтверждения. `terminal` означает окончание обработки исполнителем; очистка отдельно сохраняет незавершённые пользовательские действия и транзитивные зависимости.

Сканирование возвращает `ScanResult { installed, warnings, updatesChecked }`. UI принимает результат только актуального запроса своего режима. `requests.ts` объединяет лишь одновременно выполняющиеся read-only запросы; план и проверки перед реальными действиями не кэшируются. Полная история хранится в атомарном JSON, в UI показывается страницами по 50 задач. Каталог Rust разбирается один раз через `OnceLock`.

Приложение состоит из четырёх границ ответственности.

| Слой | Файлы | Ответственность |
| --- | --- | --- |
| Интерфейс | `src/App.tsx`, `src/styles.css` | Навигация, выбор, параметры, план, отчёт, темы и клавиатура |
| Данные и правила | `catalog/*.json`, `src/catalog.ts` | Отдельные записи продуктов, источники, редакции, расширения, наборы и зависимости |
| Адаптер и хранение UI | `src/api.ts`, `src/storage.ts` | Tauri IPC, явно обозначенный браузерный деморежим, валидация JSON, локальные настройки |
| Системное ядро | `src-tauri/src/` | Разрешённые параметры, проверка плана, очередь, WinGet, реестр, службы, порты, ярлыки и восстановление |

Rust содержит встроенную копию каталога через `include_str!` и активную проверенную версию в RwLock. Подписанные обновления могут менять только версии и описательные поля существующих продуктов; источники, опции и адаптеры требуют новой сборки. До первого React render фронтенд получает активный снимок ядра. Фронтенд передаёт внутренние ID и значения опций, а не команды, ссылки на EXE или ключи установщика. Исполняемые аргументы создаются только в ядре. Недоверенный импорт набора не расширяет разрешённые системные команды.

План получает одноразовый токен с временем действия 10 минут. До запуска пользователь видит состав, предупреждения, обнаруженные версии и доступное место. Каждая задача снова проверяет источник, архитектуру, место и обнаружение. WinGet всегда использует `--id`, `--exact`, `--source winget`; проверки хеша не отключаются.

При несовпадении хеша, отсутствии пакета, манифеста или данных источника ядро обновляет только источник `winget` и повторяет команду один раз. Закреплённая версия, область установки и остальные параметры сохраняются. Если `upgrade` не находит установленный пакет, повтор использует `install` по тому же точному ID: обнаружение в реестре не гарантирует сопоставления в WinGet. Ошибки установщика и отмена пользователем автоматически не повторяются. Команды и коды завершения записываются в журнал задачи.

Для Chrome выбран `Google.Chrome.EXE` со ссылкой Google на конкретную версию: MSI-пакет `Google.Chrome` использует изменяемый URL, для которого воспроизведено несовпадение хеша. Старый ID из экспорта WinGet приводится к новому ID продукта при обнаружении и проверке обновлений; Beta и другие каналы не объединяются.

Установки последовательны. В действии «Только скачать» допускаются 1–3 параллельных процесса WinGet. Общая пауза останавливает текущие загрузки и закрывает диспетчеризацию новых задач; отдельные кнопки управляют одной загрузкой. Для паузы / продолжения используется сохранённый дескриптор принадлежащего операции процесса и NtSuspendProcess / NtResumeProcess. Время паузы исключается из тайм-аутов и измерения скорости. Отмена завершает процесс загрузки, не запускает автоматический повтор и получает итог `cancelled`; прямые загрузки удаляют незавершённый `.part`. У WinGet могут оставаться собственные временные файлы. Процессы уже запущенных установщиков не приостанавливаются и не отменяются. Результат одной задачи не останавливает независимые. Расширения VS Code имеют родительскую задачу и отдельные результаты.

Операции WinGet `download`, `install` и `upgrade` запускаются в отдельных скрытых ConPTY через `portable-pty`: при обычном перенаправлении stdout WinGet подавляет прогресс. Счётчики переданных байтов разбираются независимо для каждой задачи; скорость измеряется с интервалом не менее 500 мс, оставшийся объём и ETA рассчитываются при известном размере. Размеры WinGet округлены самим CLI, поэтому производные показатели приблизительны. Пауза передачи обнуляет скорость, повторная загрузка сбрасывает её измерение. Проценты установки не трактуются как байты скачивания. После загрузки показатели сохраняются в строке задачи, а статус переходит к проверке файлов или установке.

Прямые образы Office скачиваются по HTTPS-ссылке доверенного каталога через Rust / reqwest без WinGet. `resumable.rs` сохраняет `.part` и версионированные метаданные, проверяет Range, Content-Range и валидатор перед дописыванием. Сетевой сбой и закрытие сохраняют часть, явная отмена её удаляет. Передача имеет сетевые тайм-ауты, паузу, ограничение скорости и общий предел 24 часа активного времени. Запись происхождения хранит точный URL и не приписывает образу проверку хеша издателя. Полные детали и правила хранения: FEATURES-2026-11-09.md.

`features.rs` — типизированная диспетчеризация фиксированных дополнительных операций IPC. `managed.rs` сериализует их с подготовкой и запуском очереди. `offline.rs` использует только встроенные рецепты EXE и SHA-256, повторно проверяет импорт и локальную копию. `preferences.rs` фильтрует настройки по разрешённым ключам / типам, хранит токены предпросмотра и отпечатки файлов, резервные копии и защиту восстановления от новых правок. `readiness.rs` содержит только скомпилированные адаптеры CLI / версий файлов. `background.rs` владеет треем, расписанием без установок, настройками, уведомлениями и отдельным потоком удержания сна.

Очередь записывается в `%LOCALAPPDATA%\app.appdock.desktop\queue.json` через временный файл, `sync_all` и переименование. После перезапуска незавершённые задачи возвращаются в ожидание; автоматического продолжения нет. Повтор всегда включает повторное обнаружение. Запущенный сторонний установщик может пережить закрытие AppDock; его состояние проверяется перед следующим запуском.

Настройки, избранное, выбор и наборы хранятся в localStorage профиля WebView2. Демоочередь имеет отдельный ключ и никогда не вызывает команды установки. В браузере рабочий режим недоступен. Серверные пароли вводятся только в мастере производителя, поэтому в данных AppDock, журналах и экспортируемых наборах полей паролей нет.

Для расширений применяется штатный CLI VS Code (`Code.exe` + `resources/app/out/cli.js`, как в `code.cmd`) без командной оболочки. `--do-not-include-pack-dependencies` не даёт расширению-пакету незаметно вернуть выключенные опции; явно выбранные зависимости устанавливаются отдельными задачами. Уже установленные расширения обнаруживаются через `--list-extensions`.

Обнаружение приложений объединяет экспорт WinGet и правила имён в реестре. Для серверов дополнительно проверяются службы. Это не определяет все возможные portable-инсталляции. Значки обновления берутся из текущего `winget list --upgrade-available`, а не из сохранённой версии каталога.

Окно адаптируется к ширине и масштабу Windows, имеет тёмную, светлую и системную темы, `Ctrl+K`, фокус и ловушку клавиатуры в модальных окнах. Контраст и уменьшение анимации управляются CSS-переменными и `prefers-reduced-motion`.

## Итерация 0.2.0

Схема очереди 2 хранит runs/currentRunId и ссылки runId у задач. PendingPlan содержит развёрнутый снимок Tasks, который переносится в очередь без перестроения. Каждая задача содержит dependencies, время активности и отдельное evidence для обнаружения и отметки пользователя. Rust типизирует статусы закрытым enum. Восстановление сохраняет параметры run.skipCurrent/parallelDownloads, не запускает очередь автоматически и повторно проверяет внешнее состояние.

UI использует события очереди и сверку раз в 15 секунд. Смена статуса сохраняется сразу, строки вывода — не чаще раза в секунду. Отказ записи приостанавливает очередь. Повреждённый снимок сохраняется в резервную копию. Детали экранов и ограничения: APPDOCK-0.2.0.md.
